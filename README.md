# IncidentIQ Backend

IncidentIQ is an AI-powered incident-response backend for software and DevOps
teams. It stores incident history in SQLite, recalls relevant operational
experience from Hindsight, sends the current incident plus that actual memory
to Groq, and validates the resulting investigation with Pydantic.

This repository intentionally contains backend code only. It does not include
React, CSS, frontend routing, or dashboard UI.

## Why persistent memory matters

An incident agent that only sees the current alert repeats investigations.
IncidentIQ retains resolved incidents as useful operational experiences:
symptoms, evidence, root cause, resolution, outcome, and lessons learned.
Future recall comes from Hindsight's retrieval system; no incident relationship
is hardcoded in the application.

## Architecture

```text
Frontend
   ↓
FastAPI Backend
   ↓
Incident Service → SQLite
   ↓
Hindsight Recall
   ↓
Groq Structured LLM Analysis
   ↓
Engineer Resolution
   ↓
Hindsight Retain
```

The Hindsight integration uses the current documented HTTP API:

- `GET {HINDSIGHT_API_URL}/health`
- `POST {HINDSIGHT_API_URL}/v1/default/banks/{bank_id}/memories/recall`
- `POST {HINDSIGHT_API_URL}/v1/default/banks/{bank_id}/memories`
- `GET {HINDSIGHT_API_URL}/v1/default/banks/{bank_id}/stats`

Groq uses its OpenAI-compatible chat completions endpoint with
`response_format.type=json_schema`. Credentials are never returned in API
responses or logged.

## Setup

Python 3.11+ is supported.

```bash
cp .env.example .env
# Set HINDSIGHT_API_URL, HINDSIGHT_BANK_ID, HINDSIGHT_API_KEY when required.
# Set GROQ_API_KEY and choose GROQ_MODEL.

pip install -r requirements.txt
```

The development environment also includes a `pyproject.toml`/`uv.lock`
generated by the package manager. IncidentIQ always uses SQLite; if an
imported workspace exposes an unrelated non-SQLite `DATABASE_URL`, the backend
uses its local `incidentiq.db` file instead.

## Run locally

```bash
PYTHONPATH=. uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

Interactive API documentation is available at `/docs`; ReDoc is available at
`/redoc`.

## Synthetic development data

The seed data is explicitly synthetic and does not represent a real company.
It contains 25 realistic resolved incidents across databases, APIs, Redis,
deployments, Kubernetes, networks, authentication, payments, and workers.

```bash
PYTHONPATH=. python scripts/seed_database.py
PYTHONPATH=. python scripts/seed_database.py --reset
PYTHONPATH=. python scripts/seed_hindsight.py
```

`seed_hindsight.py` calls real Hindsight retain for every record and exits
non-zero on missing configuration, network failure, authentication failure, or
an unconfirmed Hindsight response.

## API endpoints

### `GET /health`

Checks SQLite, Hindsight, and Groq independently. The overall status is
`ok` only when all three report `ok`; otherwise it is `degraded`.

### `POST /api/incidents/analyze`

Validates and stores a new incident, dynamically builds a recall query from
the incident, calls Hindsight, calls Groq with the current incident and actual
retrieved memories, and returns a structured analysis plus memory transparency.

### `POST /api/incidents/{incident_id}/resolve`

Stores the engineer's resolution in SQLite and retains a useful long-term
experience in Hindsight. A Hindsight failure returns HTTP 502 with
`memory_stored: false`; the SQLite resolution is not falsely rolled back.

### `GET /api/incidents`

Supports `page`, `page_size`, `service`, `severity`, and `status` filters.

### `GET /api/incidents/{incident_id}`

Returns complete incident information.

### `GET /api/memory`

Returns database-derived totals, services, recurring root causes, recent
resolved incidents, and Hindsight bank statistics only when the real Hindsight
stats endpoint is available.

## Real learning demonstration

1. Analyze a payment incident with high database CPU and query timeouts.
2. Resolve it through `/api/incidents/{id}/resolve`.
3. The backend sends that experience to Hindsight retain.
4. Analyze a genuinely related later payment incident.
5. Hindsight recall returns any relevant memory it actually finds.
6. Groq receives the current incident and that returned memory.

There is no demo mode, request counter, hardcoded similarity, or fallback
analysis.

## Testing

```bash
PYTHONPATH=. pytest -q backend/tests
```

Tests use mocks only for external Hindsight and Groq boundaries. They cover
validation, persistence, retrieval, filters, health, transparency, failure
handling, retain, and the end-to-end learning flow. Production code always
uses real HTTP integrations.

## Docker

```bash
docker compose up --build
```

The compose file mounts `./data` for SQLite persistence. The Hindsight and
Groq services must be configured in `.env`.

## Known limitations

- Hindsight and Groq credentials are required for real analysis and learning.
- Hindsight bank creation/configuration is intentionally not automated; point
  `HINDSIGHT_BANK_ID` at an existing bank supported by your deployment.
- Authentication and authorization are outside this backend contract.
- SQLite is appropriate for local and small deployments; use a deliberate
  database migration plan before moving to a multi-instance production setup.
